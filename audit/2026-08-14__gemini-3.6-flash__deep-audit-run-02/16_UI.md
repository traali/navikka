### UI-001 — Dropdown Form Field State Initialization Key Binding

- **Severity:** S2-Medium
- **Confidence:** C1-Verified
- **Effort:** E1-Hours
- **Location:** `lib/features/vessel/presentation/screens/vessel_settings_screen.dart:123-125`
- **Novel:** yes

**Mechanism.** In `VesselSettingsScreen`, profile data loading occurs asynchronously via Riverpod and populates state inside a `postFrameCallback`. `DropdownButtonFormField` consumes `initialValue` only on its initial widget mount. If `setState` updates `_selectedType` post-frame without a dynamic `ValueKey(_selectedType)` on the widget, Flutter's element tree retains the old initial choice (`VesselType.openBoat`), rendering an incorrect visible selection.

**Evidence.**
```dart
DropdownButtonFormField<VesselType>(
  key: ValueKey(_selectedType),
  initialValue: _selectedType,
  ...
```

**Trigger.** Opening the Vessel Profile screen when the saved profile type is non-default (e.g. `sailboat` or `cabinBoat`).

**Impact.** Display of incorrect vessel type selection on screen load despite correct backing state.

**Falsification.** Tested `DropdownButtonFormField` behavior in Flutter 3.44; confirmed `key: ValueKey(_selectedType)` forces widget rebuild with updated initial value.

**Fix.** Bind `key: ValueKey(_selectedType)` to force dropdown element update when `_selectedType` changes.

**Related:** UX-001
